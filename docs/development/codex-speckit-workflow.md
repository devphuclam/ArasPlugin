# Codex and OpenCode workflow

This repository supports the same Spec Kit workflow in both runtimes. The
project is currently provisioned with Spec Kit CLI `v0.13.2`.

## Canonical ownership

- `.opencode/commands/` contains the Spec Kit OpenCode integration files.
- `.agents/skills/speckit-*/SKILL.md` contains the official Spec Kit Codex
  skills generated by the `codex --skills` integration.
- `.agents/skills/{grill-with-docs,domain-modeling,codebase-design,tdd,diagnosing-bugs,code-review}/` contains the local Matt Pocock supporting skills.
- `specs/<feature>/` contains the canonical feature artifacts.

Both integration directories are generated from the same Spec Kit release. The
`.specify/integration.json` file records `codex` as the default and `opencode`
as an installed secondary integration.

## Invocation

In OpenCode, use the slash commands:

```text
/speckit.specify
/speckit.clarify
/speckit.plan
/speckit.tasks
/speckit.checklist
/speckit.analyze
/speckit.implement
/speckit.constitution
/speckit.converge
/speckit.taskstoissues
```

In Codex, invoke the matching skill by name:

```text
$speckit-specify
$speckit-clarify
$speckit-plan
$speckit-tasks
$speckit-checklist
$speckit-analyze
$speckit-implement
$speckit-constitution
$speckit-converge
$speckit-taskstoissues
```

Codex also accepts a natural-language request such as “run Spec Kit analyze
for Feature 004”. The `$speckit-*` skill invocation is the native Codex form;
repository-local files cannot register arbitrary `/speckit.*` slash syntax
inside the Codex application.

## Writer and reviewer rule

Only one runtime edits source on a branch at a time. OpenCode remains the
default implementation writer for focused Spec Kit tasks. Codex may review
artifacts or implementation, and may implement only when explicitly assigned.
No runtime may create a competing `spec.md`, `plan.md`, or `tasks.md`.

## New-session setup

After pulling a branch containing a Spec Kit upgrade, start a new Codex session
or refresh the workspace skill catalog so the ten `speckit-*` skills are
re-indexed.

## Updating Spec Kit

Check and upgrade the CLI:

```powershell
specify self check
specify self upgrade
```

Refresh an installed integration with the current CLI:

```powershell
specify integration upgrade codex --force --script ps --integration-options="--skills"
specify integration upgrade opencode --force --script ps
specify integration status --json
```

The current project intentionally keeps both integrations. Spec Kit reports
that `opencode` is not declared multi-install-safe when installed alongside
Codex; this is an upstream integration compatibility warning, not a feature
artifact failure. Review the status output after each Spec Kit upgrade.
